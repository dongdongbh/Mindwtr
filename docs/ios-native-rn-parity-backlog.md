# Native iOS: post-v1.3.2 parity and acceptance backlog

Updated: 2026-11-03. Owner: native iOS migration.

## Scope and evidence

The native app must include applicable RN mobile fixes landed after v1.3.2, not just the feature set present when migration started. This is an implementation plan, not a claim that migration is complete.

Compare v1.3.2 commit `ee82a9e3e9a1d4e0c406f5ffff80e768a1f1f812` (2026-09-22) through audited main `bd8c851d52cf0bf97340fe2d0ef32ac6603327df`. The native audit uses checkout HEAD `cf67baa008d04409220f3cb7ab07ee4885b669b8` plus its in-progress migration changes. Do not infer native parity from main containing a fix: the native bundle, Swift callers and runtime must receive it too.

The inventory is captured but behavioral reconciliation is unfinished (the UI audit currently retains 291 of 361 commits for deeper proof; the core/platform audit retains 430 of 1,212 source traces). The initial inventory contains 1,773 relevant commits, including 361 UI candidates and 1,212 core/platform candidates; these overlap and are not feature counts. Public intake enumerated 261 updated issues/PRs, 22 discussions and seven older referenced trackers. Private feedback intake enumerated 176 reports, with 37 mobile reports selected by activity since the baseline. Per-commit and feedback dispositions are still being completed. Dates alone do not establish a new requirement: check the actual resolution and whether its fix falls after the baseline.

Statuses below distinguish **confirmed gap**, **implemented / validation pending**, **verify parity**, and **device acceptance pending**. A source implementation is not a physical-device pass. Do not publish a completion percentage until the expanded inventory is classified.

The [public requirement reference appendix](ios-native-rn-parity-references.md) lists 112 issue/discussion signals, their final decisions and donor links. Use it to finish the audit; it does not promote unverified requests into native gaps.

## Implementation rules

- Reuse the maintained shared core and existing native mutation/journal owners. Port a complete fix, including later corrections, persistence and replay behavior; do not bulk cherry-pick RN UI into Swift.
- Native Swift decoders validate exact response keys. Prefer a dedicated additive read or explicit opt-in flag; coordinate any changed shape with all Swift decoders and pinned contract tests.
- Keep prior-version journals readable and their frozen effects unchanged. New behavior must not reinterpret an operation already prepared by an older app.
- Include the relevant regression, native bundle rebuild, and affected Swift/JSC checks. Run physical checks where the behavior depends on iOS permissions, lifecycle, extensions or system APIs.
- Follow the repository diagnostics ledger policy for hidden native/storage paths. Never log task text, credentials or private feedback payloads.
- Implement and independently review bounded batches. Record commit, tests and unresolved acceptance here when closing an item.
- Dropbox remains last. CI repair is outside this task. Do not replace the production app or alter production provisioning for acceptance.
