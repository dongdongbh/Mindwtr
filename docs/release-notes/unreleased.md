# Mindwtr Unreleased

Changes collected after `v1.2.1` and before the next version tag.

## Highlights

## Full Change List

- The web app (PWA and the self-hosted Docker build) can now show and open file attachments again: images, audio, text and everything else are fetched from your self-hosted Mindwtr Cloud server on demand instead of leaving an empty viewer and a dead Open button. Other sync backends, and libraries with sync encryption on, still show the not-supported notice, since the browser has no local files and no key.
- Desktop has a new read-only **Timeline** view: every task with a start or due date is drawn as a bar from start to due, grouped by project and colored the way its project dot is, with day/week/month zoom, a today line and a Today button. Dragging bars to reschedule comes later. (#1111)
- A task that has outgrown itself can now become a section of the project it is in. **Convert to Section** in the task menu, on desktop and mobile, makes a section from the task's title and notes, turns each checklist item into a task inside it (items already ticked stay done), and moves the original task to Trash, so its attachments and history remain recoverable. (#1106)
- Mobile calendar: dragging the week density slider toward more visible days no longer strands the view past the last day, where only a column or two showed next to blank space. The week re-clamps to its real width as the columns resize.
- The Tasks | Projects switch in Archived now reads **Tasks** (it borrowed the lowercase count word), and on mobile the chips no longer sit flush against the search box.
- Archived projects show their contents again. Opening an archived project from the Projects sidebar, from a task's project chip, or (desktop) by clicking its row in Archived → Projects now lists the tasks that were completed with it, on desktop and mobile. **Show completed** on an active project also reveals tasks that were archived individually. (#1019)
- Desktop: the window can no longer be scrolled or dragged past the app itself on macOS. Once a view such as the calendar with **Completed** on had scrolled to its end, the next scroll moved the whole window, sidebar included, into empty space below.
- Processing an item into a new project no longer shows a second name field: while **Make it a project** is on, the item's Title field is labeled **Project Name** and that text becomes the project's name, with the Next action below it as the first action. (#1103)
- Android WebDAV sync no longer fails with "This WebDAV server does not provide or enforce safe version checks" on a server behind a compressing proxy (nginx, Cloudflare). Android asked for compressed responses, which turn the file's version tag weak, while desktop never did, so the same server passed on desktop and failed on the phone. (#1056)
- Weekly Review's final step now shows a short "This week" look-back: actions completed, projects moved forward, and estimated vs tracked time on completed tasks when estimates are on; lines with nothing to report stay hidden.
- Focus's **Today** section now also lists next tasks that start later the same day, on desktop and mobile — sorted in with the rest of today's schedule, by their time. A task set to start at 5:00 PM used to be hidden from Next Actions until then and was too early for Upcoming, so it sat in neither section. Upcoming goes back to listing only tasks deferred to another day, and a Today row like this shows its start time until it arrives, so it still reads as later rather than doable now.
- Mobile Focus no longer shows the empty-state illustration when the only rows are in Upcoming.

- Desktop task lists now have an **Export CSV** button that exports exactly what the list is showing — the current status list plus any area, search, context, tag, priority, energy and time filters — instead of the whole database. Collapsed groups are still included, since folding a group only hides it. (#1096)
- Quick add accepts `/reference`, so a scrap of information you want to keep can be filed straight to Reference from the capture box on desktop and mobile — no capture-then-move round trip. It combines with `+Project`, `!Area`, `@context` and `#tag` like the other status tokens, and processing the inbox still ignores it so the destination you pick there wins. (#1093)
- The Pomodoro timer now sounds its end-of-session alert without needing Task reminders turned on. Task reminders are off by default, so on a new install the focus and break alerts never fired. To work in silence, turn off the new **Session-end alert** switch in Settings → GTD → Pomodoro timer. (#528)
- WebDAV sync now checks that the server returns strong ETags and enforces conditional writes before using it. Existing WebDAV setups are checked on their first sync after updating; an incompatible server stops with a compatibility error instead of risking one device overwriting another device's changes.
- File Sync keeps immutable attachment generations in the shared folder when you remove an attachment. This protects bytes that a lagging device may still reference, but the folder can grow over time. To reclaim space, back up the folder and let every device finish syncing before you remove generation files you have verified are obsolete.
- File Sync now checks a selected folder with the same atomic write used by sync before saving it, and Settings can test the folder again on demand. (#1095)
- Creating the first Someday section now groups the Someday list by those sections automatically, while later grouping choices stay yours. (#1090)
- Focus now surfaces Review Due above Next Actions on desktop and mobile, and each task appears in only its highest-priority section: Schedule, then Review Due, then Next Actions. (#1092)
- Tasks assigned to a project section now show that section beside the project name in task metadata on desktop and mobile, so their project context stays specific outside the project view. (#1091)
- Desktop Someday/Maybe keeps whole Someday projects as project rows, matching mobile, while their child tasks stay out of the Someday task list. (#1090)
- Inbox Processing now offers Area and Project before filing an item to Someday or Incubate on desktop and mobile. (#1090)
- Someday/Maybe now supports named sections that sync across devices. Rename, delete, and reorder them from Settings → Manage, or create and assign one in context while processing or editing a Someday task. (#1090)
- Processing the inbox gained **Incubate**: park an item without deciding what it is, pick a date, and it comes back to the clarify pass on that date so you can decide again. It waits in Someday/Maybe meanwhile, and the pass marks it "Back to clarify" so it doesn't read as a fresh capture. **Later** is now called **Start later** and moved next to "Yes, it's actionable", since it does what it always did — set a start date and file the task under Next Actions. Deciding to defer an action and deciding not to decide yet are different calls, and they now sit on the branch each belongs to. (#1089)
- Processing the inbox now reads the same quick-add syntax as capture: type `@phone`, `#urgent`, `!Work`, `+Existing Project`, `%Bob`, `/energy:low` or `/due:tomorrow` into the title and they land on the task instead of staying as text. Typed contexts and tags join what you picked rather than replacing it, a status token like `/waiting` is ignored so the destination you chose still wins, and a `+Name` that matches no project stays in the title — processing never creates one. Desktop also puts the cursor in the title as each item opens, at the end of the text, so a keyboard-first pass never has to reach for the mouse. (#1088)
- Sync: every cycle used to start by reconciling the saved library against the in-memory one with a full merge — the most expensive single step of an idle cycle on very large libraries. When a cheap revision check proves the two are already aligned (the usual case, since pending edits are flushed first), that merge is now skipped entirely, so background cycles that find nothing to do get dramatically shorter. (#766)
- Sync: turning on diagnostics logging no longer makes sync markedly slower on very large libraries. Each sync cycle wrote several detailed trace lines, and building one meant fingerprinting the whole library from scratch — on a 7,000-task library that was a large share of the cycle, so the log made the app slower exactly while someone was capturing one to report that it felt slow. Those fingerprints are now computed once per library version and reused. (#766)
- Sync: on very large libraries, diagnostics logging now skips the one whole-library fingerprint in each sync trace line and keeps the per-section ones, which carry the same information more precisely. A diagnostic should not be the reason the app feels slow while you are capturing a log. Ordinary libraries are unaffected and still log the full trace. (#766)
- Today's Focus now shows every starred task the focus limit counts, on desktop and mobile. A starred task inside a project moved to Someday or Waiting, in a hidden area, or with a start time later today used to disappear from the section while still occupying a focus slot — the visible result was "I can star only 4 tasks when the limit is 5", and no filter change could reveal the task holding the slot. Deferred starred tasks no longer show in Upcoming, since they now render in Today's Focus directly.
- Desktop: switching between lists or syncing no longer flashes a "Filtering..." line that shifted the whole list down a row for a moment — the banner now appears only when the filters actually changed, not when a sync refreshed the same values. Seen on every sync in Inbox, Someday/Maybe, and Waiting For. (#1079)
- Sync: merging on very large libraries is about a third faster in the common case where most tasks haven't changed since the last cycle — an unchanged task is now recognized as the same object and skips re-serialization entirely, instead of being rebuilt and re-compared field by field on every cycle. Less time mid-sync means fewer moments where a tap lands during heavy background work. (#766)
- Sync: each cycle no longer deep-copies the whole task library before checking attachments — on very large libraries that copy alone was real time per cycle, and it also forced the database to re-save every row instead of only the changed ones. (#766)
- Desktop: a start-deferred task in Focus's Upcoming section no longer shows its start date twice — the "appears on" chip now yields to the row's own start-date chip when they name the same day. With list details hidden, the appears-on chip still carries the date. (#1061)
- Desktop: Inbox rows now show their quick-complete check at rest like every other list, instead of a blank slot that only filled on hover — in mixed lists like Review the empty space read as a missing icon.
- Android: typing a note while processing the inbox no longer leaves a black band between the capture and the keyboard on some devices (seen on OnePlus 13 / Android 15) — the processing screen's window is now the same kind the app's other sheets use, which those devices handle correctly when the keyboard opens.
- Mobile: processing the inbox now asks one question at a time instead of growing a single long form. The capture stays pinned at the top with its title editable in place — clarify the wording while you decide, with the note and AI clarify one tap away — and each answer moves forward: is it actionable, does it take two minutes, who does it, is it one action. The last step shows just Project and Context, with priority, energy, estimate, tags and dates behind "More options". An icon in the processing header switches to Quick, which puts every destination on one screen and asks only the follow-up that destination needs; the choice is remembered on that device. Both finish with a buzz and an Undo toast, progress and one-tap Skip are unchanged, and every decision writes exactly what it wrote before.
- Recurrence: a monthly repeat can now land on several days of the month — pick the 1st and the 16th and the task comes back twice a month. The custom monthly editor's "Day" choice is now a grid of 1–31 you toggle, on desktop and mobile; existing single-day rules are unchanged. (#1078)
- Recurrence: a repeat that ends after a set number of occurrences now shows how far along it is — "After 6 of 10 occurrence(s)" instead of just "After 10 occurrence(s)" — on task rows and in the recurrence summary. A series with nothing completed yet still reads plainly. (#1082)
- Recurrence: monthly repeats can now target the true last day of the month (RFC 5545's BYMONTHDAY=-1) — no more starting a repeat on a 31st to get end-of-month behavior. Works in the repeat engine, calendar preview, ICS import, and the local automation API; the editors gain a "Last day" choice.
- Desktop: the Calendar toolbar gained a "Starts" toggle next to "Completed" — turn it off to hide start-date entries and read the calendar as deadlines only. On by default, remembered per device.
- Desktop: grouping a list by project no longer shows a gray header dot over rows whose project chips are colored — the group header now uses the same color the chips do: the project's area color, with the project's own color as the fallback.
- Desktop: status pills now wear their Board View colors everywhere — the status badge on task rows (lists and the review flows) and the selected status in the task editor show amber for Waiting, purple for Someday, and so on, instead of one uniform accent.
- iOS: when a storage app (Google Drive, OneDrive, ownCloud…) grays out folder selection, canceling the folder screen now explains the alternative — selecting an exported Mindwtr backup file in that app — instead of silently opening a second identical-looking picker. The in-app File Sync instructions now describe this route too. (#1068)
- Desktop: a task's quick-action menu no longer closes itself — killing the click — when the tap nudges the menu's own contents into view; taps on menu entries like Duplicate could silently do nothing. Scrolling the list behind the menu still dismisses it.
- Desktop: hand-editing `config.toml` or `secrets.toml` no longer stops the app from starting. The integrity check that guards against half-written config transactions treated any outside edit as corruption; an edited file that still reads cleanly is now accepted as the new state, and one that doesn't parse is reported with the file's name. (#1064)
- Mobile: tapping "More options" while processing the inbox now scrolls down to the options it reveals, the same way answering a processing question already follows the next step down.
- Desktop: a startup abort from the fail-closed credential recovery now writes its reason to mindwtr.log first — previously the app could exit with no window and no trace of why. (#1064)
- iOS: capture from the Lock Screen — a new "Add Task" Lock Screen widget opens quick capture directly, and on iOS 18 an "Add Task" control can replace one of the two Lock Screen bottom buttons or live in Control Center. (#1066)
- Removing an attachment now deletes its local and synced file copies on the next sync cycle instead of leaving them until a once-a-day cleanup pass. (#1064)
- Removing an attachment no longer causes recurring "Sync conflict resolved" notices: the removal is now recorded in a form every synced device agrees on, instead of a deletion the next merge kept resurrecting. (#1064)
- Calendar push on iOS and macOS: a task due on a single day without a time now lands as a one-day all-day event instead of spanning into the next day — visible in Google Calendar and any other account synced through the system calendar. (#1065)
- Desktop date fields now accept a date without a year — "1/1" means the next January 1st — and a 2-digit year, so "1/1/27" reads as 2027. (#1050)
- Mobile reminder rescheduling no longer rewrites its stored alarms or queries the system alarm list after every edit, and very large libraries stop re-serializing the whole library for a backup they already know is too big to keep. (#766)
- Large libraries: editing, completing, or adding a task now redraws lists noticeably faster. Sorting a list and rebuilding the counts behind it were re-reading the same dates thousands of times per keystroke-sized change; both now read each date once. (#766)
- Desktop: right-clicking one task and then another no longer leaves the first row wearing the highlight ring — dismissing a context menu with the pointer no longer snaps keyboard focus back to the old row. Closing the menu with Escape still returns focus to where you were. (#999)
- Desktop: the sync backend state file in your profile folder is now called `sync-backend-state.json`. It tracks whichever sync backend you picked, not just Dropbox, so the old Dropbox-specific name was misleading; existing profiles are renamed automatically on the next launch. (#1007)
- Desktop: a date field now shows a warning outline while the typed text isn't a date it can read. Nonsense never saved — it quietly reverted when you left the field — but nothing said so while you typed. (#1050)
- Desktop: the ➔ button on Waiting and Someday rows now shows a "Move to Next" tooltip on hover, and clicking it shows the same "moved to Next" toast with Undo that completing a task gets — the task no longer just vanishes from the list. (#1053)
- Pomodoro: the "Focus sessions completed" count now resets automatically at midnight and shows today's sessions, on desktop and mobile. It used to grow forever with no way to reset it. Time already credited to tasks is unaffected.
- Desktop: hovering or clicking a link in a task no longer makes the app's embedded browser engine quietly pre-connect to the linked site. Links always opened through your default browser; the engine was still warming up DNS and TLS connections to the target on its own. Link text now carries no browser-visible URL, so there is nothing left for the engine to speculate on — the URL shows in the hover tooltip and opens exactly as before. (#913)
- Mobile: checklist items can now be added straight from the two places that already show a checklist — the expanded checklist under a task row in a list, and the task preview. Type an item, press return, and the field clears with the keyboard still up for the next one, so a shopping list no longer needs a trip through the task editor's edit tab for every line. (#1055)
- Android: the Complete, Snooze, and Dismiss buttons on reminder notifications no longer go silently dead when the reminder's internal alarm record was already cleaned up — typically a notification left sitting in the tray overnight while the app rescheduled its reminders. Tapping such a button now always at least clears the notification, Complete still completes the task, and the receiver logs every tap so future reports are diagnosable. Dismissing a repeating reminder also reliably stops its sound now. (#1028)
- Desktop: section notes now show as a one-line preview right under the section header, in both the list and board layouts, so per-section guidance (like a project template's planning prompts) is visible without clicking the notes icon on every section. Hovering the line shows the full text; opening the notes editor hides the preview while you type.
- Duplicating a project now keeps reference items as references. They used to turn into Next actions along with everything else, so template projects carrying explanatory reference material gained fake to-dos on every copy. Actionable tasks still reset to Next with cleared dates and checklists, as before.
- Mobile: tapping the check icon on a search result now completes the task right there, with an Undo toast — it used to be decoration, forcing a detour through the task preview's status picker. Finished tasks show a tinted check instead. (#1051)
- Mobile: the warning and error lines in the sync settings panels (WebDAV, Dropbox, self-hosted, and the new encryption card) now use the theme's warning and error colors instead of hardcoded ones that were nearly unreadable in light mode.
- Desktop: file attachments that point outside the app's managed folder now show an Edit button in the task editor, so a link added before the pointer fix can actually be re-saved into a true pointer — previously the promised Edit affordance only appeared on attachments already typed as links. Converting one also drops the leftover synced-copy bookkeeping, and once the conversion saves, the stray copy the app had restored into its own attachments folder is deleted too. (#1001)
- Desktop: machines without a usable keyring no longer show a "Failed to check Dropbox connection status" banner when Dropbox was never set up — the status check now answers "not connected" instead of erroring when no Dropbox credentials were ever stored. A real Dropbox setup with an unreachable keyring still reports the error. (#1043)
- Desktop: tasks in the calendar's "Plan next actions" panel can now be dragged straight onto a day, matching the Schedule button and the drag support task lists already had. (#493)
- Desktop: File Sync now fails closed when the selected filesystem cannot provide a usable exclusive lock, instead of risking overlapping writers. Choose a lock-capable local or mounted folder, or use WebDAV when the mount does not support OS file locks. (#1036)
- Windows: the app log now records the exact browser-argument set WebView2 was launched with, including anything merged in from your own `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` value, so network-behavior reports can be checked against what actually applied. (#913)
- Mobile: the project menu's manual "Order" entry no longer disappears while a custom Sort is active — it now shows greyed out with an "Available when Sort is Default" hint, so manual reordering stays discoverable instead of looking like a missing feature.
- Desktop: a Dropbox setup whose credentials can't be read (for example a sandboxed install with the keyring blocked) no longer re-shows the "Failed to check Dropbox connection status" pop-up on every settings visit and sync check — the failure is reported once, and again only if it changes or comes back after a recovery. (#1060)
- Linux: the app window now shows its icon in X11 taskbars and window lists even without desktop integration — GTK silently rejects window icons as large as the one the app was setting, so panels that couldn't fall back to an installed launcher entry (like Cinnamon showing a plain AppImage) drew a blank space. (#1018)
- Quick add now understands natural-language dates in your own language when the app runs in German, Spanish, French, Italian, Japanese, Dutch, Portuguese, Russian, Swedish, or Chinese — "Appeler le dentiste vendredi prochain" detects next Friday the same way "next friday" always has, and `/due:demain` works like `/due:tomorrow`. English phrases keep working in every language, and languages without a parser keep today's English-plus-numeric behavior. (#1059)
- Android (FOSS builds): the FOSS APK build now applies the same dependency fixes as the Play build. It turned out the FOSS build recipe silently skipped every patched dependency — which is why sharing an email from FairEmail still captured the body as the task title on FOSS installs even after 1.2.0 claimed to fix it. The subject-as-title fix (and the other patched-dependency fixes) now genuinely ship in FOSS APKs, and a patch that fails to apply now fails the build instead of shipping unpatched. (#1016)
- Focus now has an "Upcoming" section, on desktop and mobile: tasks that are deferred by a start date — and recurring tasks waiting for their next date — show there for the week before they surface, sorted by the day they'll appear. No more being surprised by a recurring task the day it lands; the section only appears when something is coming, and collapses like the others. (#1061)
- Android: fixed a native crash (SIGSEGV in the SQLite bridge) that could hit when a database query finished right as the app was shutting down or restarting — the query's completion was delivered to the new JavaScript runtime while still holding handles from the old one. Seen on Play Console from Pixel Fold and Galaxy Tab devices on 1.2.1.
- Desktop: a task with a deadline on the calendar now carries its project's color (or its area's) on the chip's colored edge, the same way external events carry their calendar's color — so a month at a glance shows which project each deadline belongs to. Tasks with no project or area get a neutral edge, so a red edge is never just "no color set". Month, week, schedule, and the day panel.
- Android: adding a checklist item in the task editor no longer jumps the form back to the top of the checklist — the view stays put and the keyboard opens on the new row. The new row was being focused before it had a position on screen, so Android's scroll-into-view aimed at the wrong spot.
- Sync can now be encrypted with a passphrase, for the backends that store files you can see — File Sync, WebDAV, and Dropbox. Settings → Sync gains an Encryption section: turn it on with a passphrase (or generate a strong one), and everything the app puts in the sync location — the data file, its backups, snapshots, and attachments — is encrypted before it leaves the device; merge behavior and what other devices see in the app are unchanged. Devices without the passphrase pause syncing and ask for it once; a wrong passphrase never touches the stored files. Update every device to this version before enabling — older versions cannot read the encrypted files. Self-hosted cloud and iCloud sync are not covered, and the passphrase is unrecoverable by design. (#1056)
- Attachments now follow the file: editing an attached file after attaching it propagates the new content through sync — each sync cycle notices a changed local file (modification time and size, confirmed by content hash), re-uploads it, and other devices re-download it. Previously an attachment was a one-time snapshot and edits stayed on the device that made them. Detection of linked (external-path) files is desktop-first; phones re-download updates everywhere and detect edits to files in the app's own storage on File Sync, WebDAV, and iCloud. Two devices editing the same file still resolve whole-file last-writer-wins. A download that races a local create or edit now preserves the local generation instead of overwriting it. (#1057)
- macOS: the desktop app now ships its own widget. Adding a Mindwtr widget from the Mac widget gallery shows today's focus tasks and clicking it opens the desktop app — previously the gallery only offered the iPhone's widget over Continuity, which opened the app on the phone instead. The Mac widget also takes precedence over the iPhone one in the gallery. The widget ships in the signed Developer ID build (the DMG); the Mac App Store build gets it in a later release. (#1054)
- Desktop: Focus, Inbox, Next actions, Waiting, and Someday each remember their own "Group by" choice now. Picking a grouping on one of them used to change it on all five, so grouping Focus by project also regrouped the Inbox. Your current grouping carries over to every one of these lists on first launch, then they go their separate ways. (#1063)
- Desktop: a pending attachment delete for a sync-folder file that's already gone — for example one you deleted by hand — now resolves on the next cleanup instead of reappearing forever. File Sync treated "file not found" as a failure and kept requeueing the delete; a missing target now counts as deleted, matching the other backends. (#1064)
- Local automation API: duplicating a task or project whose attachments have synced cloud copies no longer copies the sync bookkeeping onto the duplicates — the copies used to share the original's cloud file, so syncing one could overwrite the other's content. Duplicates now re-upload as their own files, matching what duplication in the app already did. (#1057)
- Android: reminders can no longer be cancelled or fired early by other apps on the device — the alarm receivers were reachable by any installed app.
- Android: notification actions such as Complete are now only accepted from Mindwtr's own notifications — an intent sent by another app carrying a task id no longer marks that task done.
- Android: context automation triggers are now rate-limited, so a misbehaving automation app can no longer keep waking Mindwtr in the background.
- Android: app preference files are no longer enrolled in Google's automatic cloud backup and device transfer by default — the task database was already excluded, but any newly added preferences file would have been silently backed up. Sync remains the way to move data between devices.
- A failed sync cycle no longer raises a second, unobserved copy of its error alongside the one it reports — on mobile that stray copy could surface as a crash-style error overlay on top of the normal sync-failure message.
- Searching for a context or tag by its symbol ("@home", "#errand") now returns results on mobile and in the MCP server's local mode — those queries hit a search-syntax error, quietly returned nothing, and rebuilt the whole search index on every keystroke while doing it.
- Typing certain English words like "constructor" into a note no longer corrupts the text with inserted code — the markdown auto-pairing lookup treated a few words as inherited object properties. The Todoist importer similarly no longer invents a "seven days from now" due date for an unrecognized date cell.
- Importing tasks marked as reference material no longer keeps dates, recurrence, or priority on them — matching what turning a task into a reference in the app does. Previously those leftover fields showed the task on date-driven views until the first edit silently wiped them.
- A calendar-impossible date like February 31 arriving from an import or another app is now rejected instead of quietly becoming March 2.
- Duplicating a task no longer copies the original's hidden Focus position — starring the copy later dropped it into the original's old Focus slot, on every synced device.
- Completing a recurring task inside a project now keeps the next occurrence in the task's exact place in the project list — it inherits the completed task's position instead of dropping to the bottom and losing your arranged order once per cycle.
- A malformed record no longer makes the app start empty with "Failed to fetch data" — a startup data-repair step that hits one is skipped for that launch (everything else loads), reported in the log, and retried on the next launch instead of aborting the whole load.
- Bulk actions on very large lists are dramatically faster: Select All followed by Move over 50,000 tasks dropped from about 11 seconds to well under one.
- Self-hosted cloud: an automation write (adding or editing a task through the REST API) against a namespace whose stored file is corrupt or momentarily unreadable now returns an error instead of replacing the stored data with a near-empty document — and the attachment cleanup no longer deletes attachment files based on that empty view.
- Self-hosted cloud: revoking a calendar feed now removes it durably, so a revoked feed URL can no longer come back after a crash, and revoking an already-removed feed no longer errors.
- MCP server: when connected to a self-hosted cloud, list_tasks now honors the view filter (available, deferred, blocked) and the full search operator language, and due-date ranges bucket days the same way local mode does — agents asking "what's actionable" no longer receive deferred or blocked tasks.
- MCP server: importing the npm package from another script no longer starts a stdio server as a side effect and pins the process alive — the executable entry moved to its own file, and direct invocations now use dist/cli.js.
- MCP server: shutting down now closes the database cleanly (no lingering -wal files locked on Windows), and an HTTP client that disconnects mid-request no longer leaks its connection for the life of the process.
- MCP server: a mistyped flag value like --write=disabled now fails startup with a clear error instead of silently enabling the flag.
- Windows: writing a task note into an Obsidian vault no longer deletes the existing note before the replacement is in place — a crash or an antivirus lock in that moment could destroy the note. The original now survives any failed replacement.
- Desktop: Clear log now removes the rotated history file too, and a transient failure to append to the log no longer wipes the log to save one line.
- Mindwtr CSV import and export now carry recurrence. The Recurrence column was reserved but never written and always ignored on import, so repeats were the one thing a CSV migration dropped — an export now writes the repeat rule, including "repeats after completion", and importing reads it back. A rule Mindwtr cannot express, such as one built on BYSETPOS, is reported with its row number and its task arrives without a repeat instead of as an approximation of it. (#1011)
- Attachment downloads are now rejected when their contents do not match the recorded checksum — including on Android and iOS, where no checksum could previously be computed, so downloaded attachment files were never actually verified. (#1057)
- Sync downloads are now bounded, so a broken or hostile server can no longer make the app allocate unbounded memory by advertising a huge size: 100 MB per attachment and 1 GB for the sync document itself — both far above anything the app produces.
- Attachment files are now only uploaded from the app's own storage, so a tampered sync document can no longer make the app read and send an unrelated local file to the sync server. (#1057)
- Restoring a backup and the local automation API now reject attachment paths that point outside the app's attachment storage; an affected attachment is kept and marked missing rather than followed.
- Fixed attachment cleanup deleting a local file or remote copy that another task or project still referenced, when the two records spelled the same path differently (URL-encoding or path-separator variants).
- Mobile now refuses to upload attachments to a plain-HTTP WebDAV server unless insecure connections were explicitly allowed — previously the attachment bytes and credentials were sent anyway while only a warning was logged.
- Self-hosted cloud: a recurring task completed through the REST API now gets its follow-up occurrence placed in the task's spot in the project order instead of sorting to the bottom.
- Self-hosted cloud: task and project lists, single-item reads, and search now fail loudly instead of silently returning empty results when the stored sync data cannot be read.
- Restoring a backup now reliably takes effect immediately. A safety guard added against truncated reads could reject the restored document as "partial", leaving the app showing the old data while reporting success — and a later edit could write that stale data back over the restored file.
- Self-hosted cloud: the calendar subscription feed now fails loudly instead of silently serving an empty calendar when the stored sync data cannot be read.
- Self-hosted cloud: a task created through the REST API now gets its place in the project order instead of sorting to the bottom.
- Mobile sync setup now verifies the whole saved configuration at each step of a backend change, keeps an unreadable credential instead of treating it as missing, no longer drops the WebDAV certificate-exception setting, and saves reconnected Dropbox credentials only after the new settings are confirmed on disk.
- Recurring tasks: a monthly or yearly task whose start and due fall on different days no longer has its start pulled onto the due date's day-of-month. Completing "starts the 14th, due the 15th" now creates "starts September 14, due September 15" instead of a copy starting August 15 — a leftover from recurrences saved before start and due tracked their anchor days separately. Desktop, mobile, and the local automation API.
- Desktop: the task list no longer flickers on launch, window restore, or after a sync — background refreshes triggered by database file changes now compare the on-disk data first and leave the UI untouched when nothing actually changed. (#1079)
- Android/iOS: when local edits arrive during a sync and queue a follow-up cycle, the pause before that follow-up now matches how long the finished cycle took (up to five minutes) instead of being capped at one minute. On a very large library whose cycles run longer than a minute, the app no longer spends most of its time mid-sync; the queued edits still sync in the follow-up. (#766)
- Desktop: a project's "No Section" group no longer sits permanently at the front of the board. In both the board and list layouts it now appears after your named sections, and only when it actually holds tasks — while you're dragging a task it still shows up as a drop target, so dragging a task out of every section keeps working.
- Desktop: turning sync off now really turns the sync surface off. The bottom-left sync status and "Sync now" button disappear instead of offering a sync that pretends to complete, and a "conflicts resolved" notice from the last sync before the switch no longer re-toasts on every app launch. (#1001)
- Mobile: pull-to-refresh no longer shows "Please set a sync folder first" while a just-connected Dropbox setup is still verifying — the refresh now joins the running sync instead of toasting setup advice. And when sync really isn't set up, the message now matches the situation: "Please set up sync first" when sync is off, "Please connect Dropbox first" for a disconnected Dropbox, instead of folder or self-hosted-URL advice.
- WebDAV setup now recognizes a pasted Nextcloud/ownCloud web page address (the browser's `…/apps/files/…?dir=…` URL) and says what to copy instead — the WebDAV URL from Files → File settings — instead of failing every sync with "MKCOL failed (404)". (#1084)
- Desktop: opening sync settings no longer flashes a Dropbox credential error on systems without a usable keyring when Dropbox isn't the selected sync backend — the Dropbox connection check now runs only while Dropbox is selected. (#1084)
- Settings sync now carries the task editor layout — field order, hidden fields, section assignments, and which sections open expanded — under the existing GTD settings sync toggle, so a layout configured once no longer has to be rebuilt on every device.
- Sync encryption can now be set up before the first sync. Setting the passphrase with sync not yet verified used to fail with a confusing "The change could not be completed" message; it now saves the key on the device so the very first sync uploads everything already encrypted — plaintext never reaches the server. Turning encryption off in that state only removes the device's key (and says so), and operations that genuinely need the sync location, like changing the passphrase, now say to run one sync first instead of showing the generic error. If the sync location turns out to be already encrypted by another device, the first sync now asks for that location's passphrase once instead of failing every sync with a passphrase error nothing could fix. Desktop and Android/iOS. (#1001)
- Linux: pasting a screenshot into Quick Add now works. WebKit's paste event never carries clipboard images on Linux, so the paste fell through silently — Quick Add now reads the image through the browser clipboard API, which the app unlocks on its own windows. (#690)
- Desktop: area colors are no longer limited to the preset palette — the color popover gains a custom swatch that opens a small in-app picker (hue and shade controls plus an exact hex field); nothing applies until OK, so Cancel really does back out. The twelve presets stay as they are. (#1085)
- Review: a project whose only live task is a Waiting For no longer shows the red "Needs Action" badge in the weekly review and review overview — it now shows an amber "Waiting" badge, since the next step is delegated rather than missing. Only projects with neither a next action nor a waiting task count as needing action. Desktop and mobile. (#1086)
- Android: tapping a file attachment (a PDF shared in from the browser, a document, a spreadsheet) now opens it in a matching viewer app, instead of a share sheet that only offered saving or sending it. If no viewer is installed, the share sheet still appears.
- Mobile: setting up self-hosted cloud sync no longer fails with "Candidate attachment proof failed" when the library holds attachments added on another device — phones fetch attachment files on demand, so the setup verification could never prove files it did not have locally. The verification now downloads them from the server instead.
- Quick add: curly quotes now work everywhere straight quotes do — macOS smart punctuation substitutes them as you type (even the closing-style quote right after %, !, @ or #), which broke quoted names like `%"my neighbor"`. All quote styles now parse for person, area, project, context, and tag names. (#1094)
- Quick add: an `@` or `#` in the middle of a word is now left alone — pasting `Email bob@example.com` keeps the address in the title instead of turning `@example` into a context, and a `#fragment` in a pasted URL stays part of the link. Contexts and tags still parse wherever they start a word. (#1087)
- Desktop: consecutive time blocks in the calendar's day and week grids now leave a small seam between them, so back-to-back tasks read as separate items instead of one solid block.
- Flatpak: the in-app feedback form (Settings → About) now works in the Flathub build; it used to say feedback wasn't available and point at GitHub instead.
- Mobile: Focus gains the same "Hide details" toggle desktop already has — show every row with its description preview and metadata line, or just titles. Focus starts title-only, since it is the day's shortlist; the choice is remembered per device, like on desktop.
- Today's Focus limit can now be set to 1 on desktop and mobile, for people who want a single task to define the day.
- Web app (Docker/PWA): Settings -> About now shows the real app version instead of "vweb", and no longer offers the desktop update checker; the web build updates with its Docker image.
- Task rows now show a thin colored strip on the leading edge for the task's priority (red urgent, orange high, yellow medium, blue low), on desktop and mobile. It only appears when the priorities feature is enabled and a task has a priority; tasks without one are unchanged.
- Self-hosted sync settings now explain that Mindwtr doesn't use user accounts: your devices connect to your server with the access token.
- WebDAV sync: the compatibility check at the start of each sync now gets the same 30-second timeout as the rest of the sync, instead of 10 seconds. On slow or roaming connections it could time out and fail a sync whose data transfer would have succeeded, right after a previous sync had worked. The failure is also now recorded against the WebDAV backend and the `webdav_probe` step in sync history, instead of "Backend: off, Details: flush". Desktop and mobile.
- Sync: with file attachments, every sync used to write the local database again on the way out and immediately queue another sync, so the app looked like it was syncing back to back with nothing changed (and on mobile, saving sync settings could fail with "Mindwtr found new changes while testing this sync setup"). The merge dropped the device's recorded attachment file stat whenever the remote copy won a tie, and the next pass re-recorded it. It now keeps the local stat when the attachment content is unchanged. All backends, desktop and mobile.
- WebDAV sync: servers that serve `data.json` without an ETag (Jianguoyun, some nginx setups) are now re-checked for compatibility once a day instead of at the start of every sync. That check was the cold first request of each cycle and, on a slow or roaming connection, the one that timed out; when it does run it now retries transient failures the same way the sync read does. Desktop and mobile.
- Desktop (Linux/macOS): attachment downloads failed silently since 1.2.5-rc.2, and switching to or re-verifying a WebDAV/Dropbox/self-hosted sync location that already held attachments ended with "Sync setup could not be verified … Candidate attachment proof failed". The download was staged as a hidden `.download-…` file, which the file-access scope refused on Unix. Downloads and sync-location verification work again; the sync log now names a scope refusal instead of a generic failure.
- Mobile: attachment integrity hashing no longer depends on the encryption module. In Expo Go, or a build where react-native-quick-crypto cannot load, syncing a library with attachments failed verification ("Candidate attachment proof failed") and logged "Sync encryption and attachment hashing need a development build" even with encryption off; the digest now falls back to pure JavaScript there, and downloaded attachments are published from JavaScript when the native installer module is absent. Encryption itself still needs a full build.
- Mobile (Expo Go): the app no longer reports "react-native-android-widget doesn't seem to be linked" as an error on every data change when running in the Expo Go client, where that package cannot exist; it notes once that widgets are unavailable there and skips them.
- Quick add now accepts `/priority:low`, `/priority:medium`, `/priority:high` and `/priority:urgent`, so a task's priority can be typed at capture like `/energy:` already could. Desktop suggests the four levels after you type `/priority:`, and an unrecognized level is left in the title as plain text. (#1105)
- Lists and projects can now be sorted by time estimate, shortest first, with tasks that have no estimate at the end. Desktop and mobile, in the list views and the per-project sort; the option appears only while the Time estimates feature is enabled. (#1107)
- Desktop: the inline task editor now has a "Convert to Reference" button next to Duplicate, so a task can be filed as reference material without closing the editor and opening the row's ⋯ menu. It matches the mobile editor, and is hidden for tasks that are already reference. (#1108)
- Desktop: the "Convert to Reference" button briefly added to the inline task editor's footer in 1.2.5 is gone again; the action lives in the task row's right-click / ⋯ menu, where it already was. (#1108)
- Desktop: the inline task editor's footer is back to Delete, Save and Cancel. The Duplicate button and the just-added Convert to Reference button are gone; both actions live in the task row's right-click / ⋯ menu, where they already were. (#1108)
